## 一、平台简介

Nova AI Gateway 是**大模型统一接入网关**：一个 API Key、一套与 OpenAI 兼容的接口，即可调用多个主流大模型（DeepSeek、智谱 GLM、MiniMax、千问、Kimi 等），内置额度管理、按量计费、故障自动切换能力。

| 入口 | 地址 |
|------|------|
| 管理控制台 | `http://admin.starnov.cn` |
| 公开门户 | `http://www.starnov.cn` |
| API 网关 | `http://api.starnov.cn/v1` |

### 核心能力

- **统一 API 接入**：完全兼容 OpenAI Chat Completions 接口，Python / JavaScript / Go SDK 及 cURL 直接使用，仅需修改 `base_url` 与 `api_key`。
- **多 Provider 故障切换**：同一模型可绑定多个供应商，主用失败自动切换备用，对业务透明。
- **API Key 与额度管理**：支持多 Key 独立管理、随时撤销；每账号独立额度，按 Token 实时扣减。
- **按量计费**：输入/输出分开计价，支持峰谷分时定价，用量与成本实时可查。

## 二、账号开通与登录

> ⚠️ 平台**不支持自主注册**，账号由管理员在控制台统一创建并分配额度。

### 2.1 开通账号

联系管理员（或商务团队），提供姓名/邮箱，管理员在后台创建账号并配置：

| 配置项 | 说明 | 配置人 |
|--------|------|--------|
| 邮箱 | 登录账号（唯一） | 管理员 |
| 初始密码 | 首次登录凭证，建议登录后修改 | 管理员 |
| 额度 | 分配的余额（如 ¥100），调用实时扣减 | 管理员 |
| 可用模型 | 模型白名单，仅能调用已授权模型 | 管理员 |
| 状态 | 启用 / 禁用，禁用后无法登录与调用 | 管理员 |

### 2.2 登录步骤

1. 浏览器访问 `http://admin.starnov.cn`
2. 输入邮箱 + 密码登录
3. 忘记密码 → 联系管理员重置

## 三、功能操作说明

### 3.1 Dashboard（工作台）

登录后默认首页，展示当前账号的：

| 指标 | 说明 |
|------|------|
| 额度余额 | 当前剩余额度 |
| 总 Token 消耗 | 累计输入 + 输出 Token |
| 总费用 | 累计产生费用 |
| 近期调用记录 | 最近请求的模型、状态、耗时 |

> 仅展示当前账号数据，无配置项。

### 3.2 API Key 管理

> 路径：控制台「API Keys」

#### 创建 Key

1. 点击「创建 Key」（一键创建）
2. 创建成功后页面顶部弹出完整 Key，**立即复制保存**（`nv_sk-` 开头）
3. 关闭提示后完整 Key 不再展示，仅能看到前缀

#### 列表字段

| 字段 | 说明 |
|------|------|
| 前缀 | Key 前若干位（`nv_sk-xxx...`），用于识别与排查 |
| 权限范围 | 该 Key 的授权范围 |
| 状态 | 已启用 / 已撤销 |
| 创建时间 | 创建时刻 |

#### 操作

| 操作 | 说明 |
|------|------|
| 复制前缀 | 点击前缀旁复制按钮 |
| 撤销 | 确认后该 Key 立即失效，不可恢复 |
| 多 Key | 可创建多个，对应不同应用，互不影响 |

#### 安全须知

- Key 仅在创建时完整展示一次，请立即保存到安全位置
- 不要提交到 Git 仓库、前端代码、公开日志
- 如怀疑泄露，立即撤销并重新创建

### 3.3 调用 API

#### 基础参数（只需 2 个）

| 参数 | 值 |
|------|-----|
| `api_key` | `nv_sk-xxxxxxxxxxxxxxxx` |
| `base_url` | `http://api.starnov.cn/v1` |

#### cURL 快速验证

```bash
curl http://api.starnov.cn/v1/chat/completions \
  -H "Authorization: Bearer nv_sk-xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v4-pro",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

#### Python SDK

```python
from openai import OpenAI

client = OpenAI(
    api_key="nv_sk-xxxxxxxxxxxxxxxx",
    base_url="http://api.starnov.cn/v1",
)
resp = client.chat.completions.create(
    model="deepseek-v4-pro",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

#### JavaScript / TypeScript SDK

```javascript
import OpenAI from 'openai';

const client = new OpenAI({
    apiKey: "nv_sk-xxxxxxxxxxxxxxxx",
    baseURL: "http://api.starnov.cn/v1",
});
const resp = await client.chat.completions.create({
    model: "deepseek-v4-pro",
    messages: [{ role: "user", content: "你好" }],
});
console.log(resp.choices[0].message.content);
```

#### Go SDK

```go
client := openai.NewClientWithConfig(
    openai.DefaultConfig(
        "nv_sk-xxxxxxxxxxxxxxxx",
        "http://api.starnov.cn/v1",
    ),
)
resp, _ := client.CreateChatCompletion(
    context.Background(),
    openai.ChatCompletionRequest{
        Model:    "deepseek-v4-pro",
        Messages: []openai.ChatCompletionMessage{{Role: "user", Content: "你好"}},
    },
)
println(resp.Choices[0].Message.Content)
```

#### 现有 OpenAI 代码迁移

只需改 3 处，业务逻辑零改动：

| 参数 | 原值 | 新值 |
|------|------|------|
| `api_key` | OpenAI Key | 网关 Key（`nv_sk-` 开头） |
| `base_url` | `https://api.openai.com/v1` | `http://api.starnov.cn/v1` |
| `model` | OpenAI 模型名 | 网关上的模型名 |

#### 图像生成（如已授权）

```bash
curl http://api.starnov.cn/v1/images/generations \
  -H "Authorization: Bearer nv_sk-xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model": "图像模型名", "prompt": "一只在月球上喝咖啡的猫"}'
```

## 四、功能配置说明（管理侧）

以下功能由**管理员**在控制台配置，直接影响用户可用范围。用户如遇额度 / 模型 / 价格问题，可对照本节向管理员说明。

### 4.1 Provider 管理

> 路径：控制台「Providers」→ 添加 Provider

| 配置项 | 必填 | 说明 | 示例 |
|--------|:---:|------|------|
| 名称 | ✅ | 供应商标识 | `DeepSeek官方` |
| Base URL | ✅ | 厂商 API 域名（不带路径） | `https://api.deepseek.com` |
| API 路径 | ✅ | 调用接口路径 | `/v1/chat/completions` |
| API Key 引用 | ✅ | 该厂商的真实 Key | `sk-xxxx` |
| 优先级 | ✅ | 数值越小越优先（路由顺序） | `1` |
| 权重 | ✅ | 同优先级流量占比 | `100` |
| 启用 | ✅ | 关闭后不参与路由 | 勾选 |

### 4.2 模型管理

> 路径：控制台「模型管理」→ 添加 Model

| 配置项 | 必填 | 说明 |

## 五、端到端流程：配置供应商 → 配置模型 → Trae 调用

### 第一步：配置供应商（Provider）

> 路径：控制台「Providers」→ 添加 Provider

1. 点击「添加 Provider」
2. 填写：名称、Base URL（厂商域名）、API 路径、API Key 引用、优先级、权重、启用
3. 保存后列表出现该 Provider，状态显示「启用」

### 第二步：配置模型（Model）

> 路径：控制台「模型管理」→ 添加 Model

1. 点击「添加 Model」，填写名称、编码（modelCode）、模型类型、是否公开
2. 创建后点击「+ 绑定 Provider」：选择供应商、权重、API 路径覆盖（留空用默认）
3. 进入「定价」为该模型配置单价，保存后状态为「已配置」

### 第三步：开通账号 + 创建 API Key

1. 「账号管理」→ 创建账号：邮箱、初始密码、昵称；进入详情设置额度 + 勾选模型白名单
2. 「API Keys」→ 创建 Key → 复制完整 Key（`nv_sk-` 开头，仅显示一次）

### 第四步：Trae IDE 中配置调用

1. 打开模型管理入口：**设置 → 模型 → 添加模型**（或 AI 对话框右下角模型列表 → 添加模型）
2. 选择 **「自定义配置」**
3. **API 格式**：选择 **「OpenAI Chat Completions 格式」**
4. **请求地址**：关闭「完整 URL」开关，填 `http://api.starnov.cn/v1`（开启则填 `http://api.starnov.cn/v1/chat/completions`，二选一）
5. **模型 ID**：填网关上的 modelCode，如 `deepseek-v4-pro`（必须与后台完全一致，大小写敏感）
6. **API 密钥**：填 `nv_sk-xxxxxxxxxxxxxxxx`
7. 点击「添加模型」→ Trae 自动预检，成功后出现在模型列表
8. 回到 AI 对话框，选中该模型，发测试消息验证

### 第五步：验证计费与用量

- 调用成功后 Token 消耗实时扣减账号额度
- 「我的用量」可查本次调用的模型、费用、延迟、状态
- 额度不足返回 `402 QUOTA_EXCEEDED` → 联系管理员充值

### 完整链路图

```text
管理员在后台配置         用户使用
───────────────         ──────────────
① Provider 管理          ④ Trae 自定义模型
  (Base URL+API路径+Key)    ├ API格式: OpenAI
        │                   ├ 请求地址: api.starnov.cn/v1
② 模型管理                 ├ 模型ID: deepseek-v4-pro
  (modelCode)              └ API Key: nv_sk-xxx
   └─ 绑定 Provider ──→ ⑤ 发消息 → Gateway 鉴权+路由+计费
③ 定价 + 账号额度              └─→ 上游 DeepSeek 等厂商
```

## 六、计费与额度规则

| 规则 | 说明 |
|------|------|
| 计费方式 | 按实际 Token 消耗，输入 / 输出分开计价 |
| 流式请求 | 按响应末尾 `usage` 字段统计，同样计费 |
| 图像生成 | 按张数计费（支持分辨率阶梯价） |
| 峰谷计价 | 分时段模型按高峰 / 低谷单价计费 |
| 额度扣减 | 行级锁保证准确性，不足返回 402 |
| 额度不足 | 返回 `402 QUOTA_EXCEEDED` → 联系管理员充值 |

## 七、错误码速查

| 错误码 | 含义 | 处理 |
|:---:|------|------|
| 401 | Key 无效 / 未携带 | 检查 `Authorization: Bearer nv_sk-...` |
| 402 | 额度不足 | 联系管理员调整额度 |
| 404 | 模型不存在 / 未授权 | `GET /v1/models` 确认模型名与权限 |
| 429 | 触发限流 | 降低频率，稍后重试 |
| 500 | 服务内部错误 | 记录请求信息，联系管理员 |
| 503 | 模型无可用 Provider | 管理员检查 Provider 配置 |

**Trae 侧常见报错：**

| 报错 | 原因 | 处理 |
|------|------|------|
| 401 Unauthorized | API Key 错误 | 重新复制 `nv_sk-` Key，检查空格 |
| 404 Model Not Found | 模型 ID 与网关 modelCode 不一致 | `GET /v1/models` 核对模型名 |
| 402 QUOTA_EXCEEDED | 账号额度不足 | 联系管理员充值 |
| 连接超时 | 网关不可达 / 地址填错 | 检查 `http://api.starnov.cn/v1`，是否漏 `/v1` |
| 503 | 模型未绑定可用 Provider | 管理员检查 Provider 启用与绑定 |

## 八、最佳实践

1. **Key 隔离**：不同应用用不同 API Key，泄露时单独撤销，不影响其他应用
2. **成本控制**：批量 / 低优任务用 flash 版模型，重要对话用 pro 版；善用峰谷低价时段
3. **流式输出**：长回答建议开启 `stream: true`，降低首字延迟
4. **重试策略**：429 / 5xx 指数退避重试，避免雪崩
5. **定期巡检**：每周查看「我的用量」核对成本，及时发现异常
