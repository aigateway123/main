## 1. 目标与定位

### 1.1 目标

在「Skill 商城」基础上新增 **专家团** 业务线：把多个 Skill 编排成**多专家协作流程**，一个任务由一支 AI 团队分工完成。

> 一句话定位：**「专家团」= 多个 AI 专家的协作流程。单个 Skill 是一个人干活，专家团是一支团队干活。**

对应商业模式 V2 升级路径：

```
Layer 2 AI Skills（单点能力，已上线商城）
        ↓ 组合编排
Layer 3 Expert Team（多专家协作流程，本次新增）→ B2 升级为定制 AI 员工
```

### 1.2 与现有页面/产品的边界

| 对比对象 | 差异 | 定位 |
|---------|------|------|
| Skill（商城） | 单 Skill = 单能力单角色 | 专家团由多个 Skill 组成，含**角色分工 + 协作顺序** |
| Solution（解决方案） | 行业大方案展示（B 端、高价、静态 pipeline） | 专家团是**可购买、可在线协作体验**的产品单元，粒度更细 |
| AI 员工（B2） | 定制化、接知识库、私有化 | 专家团是标准化的 AI 员工雏形，先行验证协作价值 |

### 1.3 本次范围

- ✅ 专家团列表页 + 详情页（含**协作流程图**）+ 在线协作体验页
- ✅ 专家团卡片展示角色构成、协作流程、定价、适用场景
- ✅ 购买引导（UI 闭环，复用 Skill 购买模式）
- ✅ 首页 + 导航新增专家团入口
- ✅ 延续紧凑卡片式设计（WorkBuddy 风格，与 Skill 商城一致）

### 1.4 非目标

- ❌ 不建设后端 Agent 编排 / 工作流引擎（B1 平台迭代，单独排期）
- ❌ 不做自定义专家团（用户自由拖拽组队）
- ❌ 不做 AI 员工定制（B2 再做）

## 3. 专家团页面规划

### 3.1 专家团列表页 `/teams`

**结构**（紧凑卡片式，对齐 Skill 商城风格）：

```
┌────────────────────────────────────────────┐
│ Header：专家团 · 一支 AI 团队，协作完成一件事    │
│ [搜索框]  [场景 Tab: 全部/投标/外贸/内容增长]     │
│                                            │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐    │
│ │ 团队卡片   │ │ 团队卡片   │ │ 团队卡片   │ 4列网格│
│ └──────────┘ └──────────┘ └──────────┘    │
│                                            │
│ CTA：定制你的 AI 员工（升级路径）              │
│ Footer                                     │
└────────────────────────────────────────────┘
```

**团队卡片字段**：

| 字段 | 说明 |
|------|------|
| 团队图标 / 名称 | 如「投标作战团」 |
| 场景标签 | 投标 / 外贸 / 内容增长 |
| 一句话卖点 | 解决什么任务 |
| **成员构成** | 2~3 个专家头像 + 名字（如：投标经理 + 合同审查 + 数据分析） |
| **协作方式** | 并行 / 串行 / 混合 徽章 |
| 定价 | 团队价（如 ¥899 起） |
| 操作 | 「查看协作流程」「开始协作」 |

### 3.2 专家团详情页 `/teams/:slug`

| 区块 | 内容 |
|------|------|
| 顶部 | 团队图标 + 名称 + 场景 + 成员构成 + 团队价 |
| 主 CTA | 「立即购买」「免费在线协作」双按钮 |
| **协作流程图（核心）** | 可视化展示：任务 → 总指挥拆解 → 各专家分工（并行/串行）→ 汇总交付 |
| 专家列表 | 每位专家：角色头像 + 负责环节 + 用到的 Skill + 输入/输出 |
| 价值亮点 | 3~4 个能力点（比单 Skill 强在哪：分工明确 / 全流程覆盖 / 质量互检） |
| 效果示例 | 输入 → 协作过程 → 交付物（静态展示多步输出） |
| 定价 | 团队套餐（含成员 Skill 组合价，或 Basic/Pro/Business 三档） |
| FAQ | 该团队常见问题 |

**协作流程图设计**（核心差异化，参考 WorkBuddy 多专家协作）：

```
┌────────────┐
│ 你下达任务   │  一句话描述目标
└─────┬──────┘
      ▼
┌────────────┐
│ 总指挥拆解   │  规划步骤 + 分配专家
└─────┬──────┘
      ▼
┌────────────────────┬────────────────────┐
│ 专家A（第一步）       │ 专家B（并行/第二步）   │
│ 如：投标经理·读标    │ 如：合同审查·风险识别  │
└────────┬───────────┴────────┬───────────┘
         ▼                     ▼
┌────────────┐          ┌────────────┐
│ 专家C（汇总） │◄─────────│  中间产物    │
│ 数据分析·测算 │          └────────────┘
└─────┬──────┘
      ▼
┌────────────┐
│ 交付成果     │  结构化报告 / 文档 / 图表
└────────────┘
```

> 每步节点展示：专家头像、职责、输入来源、输出产物、耗时（Mock）。

### 3.3 在线协作体验页 `/teams/:slug/use`

MVP 采用「**多步协作模拟**」：按协作流程逐步播放，每步显示对应专家「在工作」，最终汇总为完整交付物。

| 区块 | 内容 |
|------|------|
| 左侧 | 任务输入表单（一个总目标，如投标：粘贴招标文件） |
| 中间 | **协作过程舞台**：步骤卡片按流程依次高亮（专家头像 + 状态 + 产物） |
| 右侧 | 汇总输出区（流式输出最终交付物，可下载 Markdown） |
| 顶部 | 返回团队详情 + 运行控制（开始 / 暂停 / 重置 / 跳过步骤） |

> 与 SkillUsePage 单输入单输出的差异：这里是**多专家接力**，每步产出中间结果，最终合并。

### 3.4 购买流程（UI 闭环）

复用 Skill 购买模式：

```
详情页点击「立即购买」
    ↓
确认订单弹窗（团队名称 / 套餐 / 价格 / 包含 Skill 清单）
    ↓
支付成功 → 「开始协作」入口
```

## 4. 数据方案

| 数据 | 来源 | 说明 |
|------|------|------|
| 专家团列表 | `src/data/expertTeams.ts`（Mock） | 每个团队一个对象 |
| **成员 Skill** | 引用 `skills.ts` | 专家团成员复用现有 Skill 定义，展示时可跳转对应 Skill 详情 |
| 协作流程 | `expertTeams.ts` 内 `pipeline` | 节点顺序 / 并行关系 / 每步输入输出 |
| 订单 | Mock | 复用 Skill 购买模式，B1 接后端 |

**类型扩展**（`types/index.ts`）：

```ts
export type TeamFlowNode = {
  step: number
  role: string          // 专家角色名，如「投标经理」
  skillSlug: string     // 关联 Skill
  mode: 'plan' | 'parallel' | 'sequential' | 'merge'   // 总指挥/并行/串行/汇总
  title: string         // 该步做什么
  description: string
  input: string         // 输入来源描述
  output: string        // 输出产物描述
  duration: string      // 预估耗时（Mock）
}

export interface ExpertTeam {
  slug: string
  name: string
  industry: string      // 投标 / 外贸 / 内容增长
  tagline: string
  description: string
  icon: string
  badge: string         // 并行 / 串行 / 混合
  price: string
  highlights: string[]
  scenarios: string[]
  members: { skillSlug: string; role: string; responsibility: string }[]  // 团队成员
  flow: TeamFlowNode[]  // 协作流程（核心）
  inputFields: SkillInputField[]
  sampleTask: string    // 示例任务
  sampleDeliverable: string  // 最终交付物示例
  faq: FaqItem[]
  status: 'online' | 'coming-soon'
  plans: SkillPlan[]
}
```

**首批专家团清单（3 个，组合现有 6 个 Skill）**：

| # | 专家团 | 成员（Skill） | 协作方式 | 定价带 | 场景 |
|:-:|-------|--------------|:-------:|--------|------|
| 1 | **投标作战团** | AI投标经理（指挥/读标）+ AI合同审查（风控）+ AI数据分析（商务测算） | 混合（读标→并行走合同审查与测算→汇总） | ¥899~1,999 | 从招标到投标全流程 |
| 2 | **外贸出海团** | AI外贸销售（获客）+ AI营销文案（内容）+ AI数据分析（市场） | 混合 | ¥699~1,699 | 询盘→报价→营销内容 |
| 3 | **内容增长团** | AI内容运营（规划）+ AI营销文案（生产）+ AI数据分析（复盘） | 串行（规划→生产→复盘循环） | ¥599~1,499 | 内容全链路 |

## 5. 技术方案

### 5.1 路由引入

```
src/
├── pages/
│   ├── TeamsPage.vue        # 专家团列表
│   ├── TeamDetailPage.vue   # 详情（含协作流程图）
│   └── TeamUsePage.vue      # 在线协作体验
├── components/
│   └── team/
│       ├── TeamCard.vue         # 列表卡片（成员头像组）
│       ├── TeamFlowDiagram.vue  # 协作流程图（核心组件）
│       └── TeamMemberBadge.vue  # 专家徽章
├── data/
│   └── expertTeams.ts       # 新增
├── types/index.ts           # 扩展 ExpertTeam / TeamFlowNode
└── router/index.ts          # 新增 /teams 三个路由（懒加载）
```

### 5.2 路由配置

```ts
{
  path: '/teams',
  name: 'teams',
  component: () => import('@/pages/TeamsPage.vue'),
},
{
  path: '/teams/:slug',
  name: 'team-detail',
  component: () => import('@/pages/TeamDetailPage.vue'),
},
{
  path: '/teams/:slug/use',
  name: 'team-use',
  component: () => import('@/pages/TeamUsePage.vue'),
},
```

### 5.3 视觉规范

完全延续 Skill 商城刚定稿的**紧凑卡片式设计**（WorkBuddy 风格）：
- 卡片 `p-4 rounded-2xl`、4 列网格、小字号信息密集
- 主色 `blue-600 → indigo-600` 渐变体系不变
- 协作流程图用「节点 + 连线」表达（flex/absolute 连线，无需图表库）
- 成员头像组用「重叠圆形头像」表达团队感

## 7. 风险与开放问题

| # | 风险 | 等级 | 缓解 |
|---|------|:---:|------|
| 1 | 专家团与解决方案页定位重叠，用户困惑 | 中 | 首页/导航明确区分：专家团=可购买产品，解决方案=行业大方案 |
| 2 | 多步协作模拟复杂度高于单 Skill 试用 | 中 | 流程固定为 3~5 步，先做 Mock 播放，不做自由编排 |
| 3 | 团队组合价与单品价格体系冲突 | 低 | 团队价 = 成员组合 + 协作编排溢价，文档中明示含哪些 Skill |

| # | 开放问题 | 决策 |
|---|---------|------|
| 1 | 首批专家团是否按「投标/外贸/内容增长」3 个执行？ | 待 CEO 确认 |
| 2 | 在线协作体验是 Mock 播放，还是接真实 Chat 多轮调用？ | 待 CEO 确认（建议 Mock，与 Skill 商城一致） |
| 3 | 团队套餐定价：直接打包价 or 三档 Basic/Pro/Business？ | 待 CEO 确认（建议三档，与 Skill 一致） |
| 4 | 导航「专家团」放 Skill 商城旁，是否影响现有转化路径？ | 待 CEO 确认 |
