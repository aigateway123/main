## 2. Product Background

### 为什么需要门户网站

Nova AI Gateway 目前已具备较完整的 AI Gateway MVP 功能（统一 API 接入、多 Provider 管理、智能路由、API Key 管理、用量统计与计费、Admin 后台管理），但**完全缺乏对外展示的窗口**。

当前状况：
- 没有公司官网或产品 Landing Page
- 潜在用户无法了解产品能力和价值
- 没有用户注册和转化的入口
- 品牌认知度为零——用户只能通过口碑或直接联系才能知道 Nova AI Gateway

### 行业背景

AI Gateway 赛道正在快速成熟。2026 年的市场趋势：

| 维度 | 趋势 |
|------|------|
| 竞争格局 | Cloudflare AI Gateway、Portkey、OpenRouter 等成熟产品已有完善的营销站点 |
| 用户决策 | 开发者/企业选型 AI Gateway 时，官网是第一个接触点 |
| SEO 价值 | 产品官网是自然流量的核心来源 |
| 品牌信任 | 没有官网的产品让企业客户缺乏信任感 |

竞争对手均有成熟的营销站点：
- Cloudflare AI Gateway：完整的产品官网 + 文档站 + 开发者社区
- Portkey：功能丰富的 Landing Page + 定价页 + Blog
- OpenRouter：简洁的模型展示 + API 文档

### 用户需求

- **开发者**：想了解 Nova AI Gateway 支持哪些模型、API 是否兼容 OpenAI、如何接入
- **企业决策者**：需要评估产品的稳定性、安全性、成本优势
- **潜在客户**：需要一个自助注册入口，先体验再决定是否付费
- **已有用户**：需要从官网直接跳转到 Admin 控制台

## 3. Problem Statement

Nova AI Gateway 有完整的产品能力，但没有面向公众的展示入口，导致"产品存在但无人知晓"的问题。

| 问题 | 影响 |
|------|------|
| 无可访问的官网 | 搜索引擎无法索引产品信息，自然流量为零 |
| 无用户获取渠道 | 潜在用户无法了解产品、无法注册、无法试用 |
| 品牌空白 | 在客户沟通、商务合作时无法提供官方展示页面 |
| 缺乏信任基础 | 没有官网让企业客户质疑产品的正规性和可持续性 |

## 4. Goals

### 产品目标

- **G1**: 上线 Nova AI Gateway 门户网站 MVP，展示产品的核心能力和价值主张
- **G2**: 提供用户注册/登录入口，打通从官网到 Admin 控制台的转化路径
- **G3**: 在 MVP 上线首月内获得至少 100 次独立访客访问
- **G4**: 建立品牌基础视觉体系，为后续的 SEO、内容营销、文档站奠定基础

### 非目标

- **不在 MVP 范围**：用户自助注册功能（MVP 阶段仅提供"登录控制台"入口，注册由后台手动管理）
- **不在 MVP 范围**：多语言国际化（MVP 仅支持中文，英文站为 P1）
- **不在 MVP 范围**：Blog/News 内容管理系统（后续通过 Markdown 静态页面补充）
- **不在 MVP 范围**：在线 API Playground（属于 P3 Developer Platform 范围）
- **不在 MVP 范围**：SEO 优化和搜索引擎收录优化（MVP 先上线内容，后续迭代优化）
- **不在 MVP 范围**：后端改动（门户 MVP 阶段是纯前端项目，所有数据使用静态数据）

|------|---------|---------|

- **预期 ROI**：MVP 阶段为纯投入，为后续获客奠定基础

## 6. User Story

### 核心用户故事

- **作为开发者**，我希望通过官网快速了解 Nova AI Gateway 支持哪些模型和 API 兼容性，以便评估是否适合我的项目。
- **作为企业决策者**，我希望了解 Nova AI Gateway 的稳定性、安全性和成本优势，以便做采购决策。
- **作为潜在客户**，我希望从官网直接进入 Admin 控制台注册/登录，以便快速体验产品。
- **作为已有用户**，我希望通过官网找到登录入口和文档链接，以便日常使用和管理。

### 用户角色

| 角色 | 描述 | 主要需求 |
|------|------|---------|
| 独立开发者 | 个人开发者，需要接入 AI 模型 API | 了解 API 兼容性、模型支持、定价；快速注册使用 |
| 初创团队 CTO | 小团队技术负责人，评估 AI 基础设施 | 评估产品功能完整性、成本和稳定性 |
| 企业 IT 决策者 | 大中型企业的 IT 负责人 | 关注安全合规、SLA、企业级功能 |
| 已有注册用户 | 已拥有 Nova AI Gateway 账号的用户 | 快速找到登录入口进入 Admin 控制台 |

## 9. User Flow

### 主流程：访客浏览 → 登录控制台

```
访客通过搜索引擎/链接进入官网
    │
    ▼
浏览 Hero 区（了解产品定位）
    │
    ▼
滚动浏览 Why Section（了解产品优势）
    │
    ▼
查看模型展示区（了解支持的模型）
    │
    ▼
浏览基础设施 / 定价信息
    │
    ▼
点击 "登录控制台" CTA 按钮
    │
    ▼
跳转到 Admin 登录页面（/login）
    │
    ▼
输入账号密码登录
    │
    ▼
进入 Admin Dashboard
```

### 主流程：访客浏览 → 查看文档

```
访客浏览官网
    │
    ▼
点击 "查看文档" CTA 或导航中的"文档"
    │
    ▼
跳转到文档页面（后续开发，MVP 阶段可链接到 GitHub Wiki 或暂缺）
```

### 异常流程

- **CTA 跳转时未登录**：直接跳转到 Admin 登录页，登录后重定向到 Dashboard
- **移动端浏览**：导航栏折叠为汉堡菜单，所有内容区自适应
- **页面加载失败**：显示友好的错误提示，不影响其他功能

## 11. API Impact

门户 MVP 阶段**不做后端改动**，所有展示数据使用静态数据。

后续迭代可能需要新增以下 API（当前仅记录，不在 MVP 实现）：

| 接口 | Method | 变更类型 | 说明 |
|------|--------|---------|------|
| `/api/v1/public/models` | GET | 新增 | 对外公开的模型列表（供门户展示） |
| `/api/v1/public/stats` | GET | 新增 | 平台公开统计数据（用户数/请求数等） |
| `/api/v1/public/pricing` | GET | 新增 | 对外公开的定价信息 |

### 向后兼容

全部为新增接口，无向后兼容问题。

## 13. Risks

| # | 风险描述 | 等级 | 可能性 | 影响 | 缓解方案 |
|---|---------|------|--------|------|---------|
| 1 | **品牌风格不一致**：门户设计与 Admin 后台视觉风格差异过大 | 中 | 中 | 用户认知混乱 | 门户和 Admin 使用同一套设计 Token 体系（颜色/字体/间距） |
| 2 | **SEO 效果不佳**：纯前端 SPA 对搜索引擎不友好 | 中 | 高 | 自然流量获取困难 | MVP 阶段先保证内容完整；后续考虑 SSR 或 SSG |
| 3 | **部署复杂度增加**：新增 portal 服务需要更新 Nginx 和 Docker Compose | 低 | 中 | 部署失败 | portal 使用与 admin 相同的部署方式（vite build → nginx 静态文件） |
| 4 | **内容过时**：静态数据未及时更新，展示模型/定价与实际不符 | 中 | 中 | 用户误解 | 在代码中标注数据更新时间，建立定期更新提醒 |
| 5 | **移动端体验不达标**：响应式设计覆盖不全 | 中 | 低 | 移动端用户流失 | 使用移动优先设计，在至少 3 种屏幕尺寸上验证 |
