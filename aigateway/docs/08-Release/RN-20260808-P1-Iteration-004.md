## 2. 功能范围

### 2.1 计价单位 per_million_tokens（按百万 Token）【P0】

| # | 功能 | 状态 |
|:-:|------|:----:|
| 1 | Admin 前端：定价编辑弹窗「计价单位」下拉新增「按百万 Token」选项（value=per_million_tokens），与 token 共用统一定价(flat)/分时段(time_based)表单，单位提示随单位动态切换（per token / per million tokens），列表价格详情加 /M 标注 | ✅ |
| 2 | 后端计费（billing_service.go ComputeCost）：`cost = (inputTokens×输入百万单价 + outputTokens×输出百万单价) / 1,000,000`；峰谷(time_based)时段取价后同样除以 1,000,000 | ✅ |
| 3 | 计费保护：calculateImageCost fallback 对 per_million_tokens 单位同步除 1M，避免百万倍金额偏差 | ✅ |
| 4 | 定价状态自动判定：per_million_tokens 的 flat（价格>0）与 time_based（配置峰谷价）均可自动判定为 active | ✅ |

## 3. 关键验证结论

测试方式：ECS 本地回环 mock Provider（OpenAI 兼容端点，固定 usage 100/200）走完整链路，零真实厂商费用；测试数据已全部清理恢复。

| # | 验证项 | 结果 |
|:-:|--------|:----:|
| 1 | 非流式 usage(100/200) + flat（输入 2/百万、输出 6/百万）→ `costAmount=0.0014` | ✅ 精确匹配公式 |
| 2 | 流式（SSE 末块 usage）→ 同样 `0.0014` | ✅ |
| 3 | 峰谷峰值时段（3/9）→ `0.0021` | ✅ |
| 4 | 额度扣减累计 `0.0049` 与 quotaBalance/totalSpent 一致 | ✅ |
| 5 | token 单位回归不受影响（100×0.000002 + 200×0.000006 = 0.0014，无 /1M 缩放） | ✅ |

## 5. 已知限制与注意事项

1. **存量定价数据不变**：新增 `per_million_tokens` 单位后，存量 token 定价数据保持不变。如需按百万 Token 计价，需管理员手动在后台调整相应模型定价。
